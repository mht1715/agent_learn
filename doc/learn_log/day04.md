# 目标

- 实现一个简单的rag，准备语料、切分、向量化、嵌入、内存检索（先不做数据库检索）

# 学习内容

- 在 `rag/corpus` 下准备了8条关于订单的语料
- 第一步先读取目录下的语料，准备好语料文档数组
- 准备好文本切割器 `splitter`,`RCTS`快捷生成，设置块大小、重叠大小、分割符
- 遍历分块，用嵌入模型将分块先量化、归一化，目前暂时只是保存在内存中
- 用嵌入模型检索，召回知识，后续拼接到上下文中
# 踩坑

- 需要分批10次，原因是 DashScope 单次最多 10 条，超过直接报错
- 归一化有难度，还是找靠谱的或者让ai封装一个工具类比较合适，不要执着于这里，不然学不下去了
- 检索出来了，但是检索出来的结果效果不是很好，还有很大的优化空间

# 思考

- rag好像就是准备知识语料，分割切块，将每个块向量化，保存到向量数据库
- 我发现这样切割出来的语料效果好像不是很好，直接切割出来的语块只是按照固定的大小或者结束符，每块内容看着不太可以，检索出来的结果也是不完整的
- 语料应该需要人工或者agent处理好之后再存到向量库
- 目前检索出来的数据效果不是很好，后续还能优化
- 归一化应该是优化计算速度的，不太懂，有难度，记不住，后续让ai写几个工具类来用
- 检索就是把用户问题也向量化，然后和向量库里的向量进行相似度对比，最后得出结果，如果结果不好后续应该就是重排序或者还有其他的处理
